# CrossChat Hub v0.3 — User-first Windows / macOS Messaging Desktop

CrossChat Hub is moving from an administrator-oriented Bot gateway to a **user-facing,
multiple-account desktop client**. The first screen is now **Sign in to your accounts**;
Bot secrets, Webhooks, custom identity aliases and bridge rules are available only within
an expandable **Developer / Advanced Integration** area.

## User login and honest platform capabilities

| Platform | End-user sign-in | Personal chat support in v0.3 |
| --- | --- | --- |
| Slack | OAuth **user** token (app registration required once) | List permitted rooms, read 50 recent messages, send to a permitted room |
| Discord | Official OAuth `identify` | **Identity only**, cannot read/impersonate personal DMs |
| LINE | Official LINE Login (profile/openid) | **Identity only**, no access to personal LINE chat via LINE Login |
| Telegram | Official MTProto/TDLib possible | **Not implemented yet**: v0.3 does not offer fake Telegram QR/phone login |

The existing Bot-based channel-to-channel bridges and mention notifications still exist,
but are **advanced integrations** rather than login. Never use ordinary account passwords,
third-party browser cookies or personal Discord tokens to simulate unsupported APIs.

**OAuth application setup is an operator/developer responsibility**. End users never type Bot
Tokens or Webhook Secrets into the sign-in screen. A desktop binary alone cannot
secretly ship a third-party OAuth app's `client_secret` safely. Set up provider OAuth
client IDs/secrets in the desktop app's user settings or use a secure hosted OAuth
broker. Some providers require a public HTTPS callback, not loopback HTTP; that must
be provisioned separately.

At present, `@platform:alias` routes through explicitly authorized Bot/channel
connections. An identity-only LINE or Discord login **does not** enable delivery
as that user. Real cross-platform personal-chat synchronization depends on platform
permissions and is not implemented across all providers.

## Verification

- External live OAuth and personal chat sessions require real developer apps and accounts.

## Quick start — Web/daemon mode (Node.js >= 22.13)

```bash
npm run setup
npm test
npm start
# Open http://127.0.0.1:8787
```

The `.env` file (generated by setup) includes strong keys and is gitignored.
To receive external webhooks, configure a public HTTPS reverse proxy; otherwise
only local API use and outbound Discord Gateway work.

## Desktop mode

```bash
npm install               # requires npm registry access
npm run desktop           # native window, Windows or macOS
npm run desktop:win       # Windows installer (run on Windows)
npm run desktop:mac       # macOS dmg + zip (run on macOS)
```

The desktop app creates its own user-profile encrypted database and auto-generated
admin keys on first launch. No separate Node.js runtime is required **after packaging**.
The desktop and local daemon store **separate** data by default. See
[docs/desktop.md](docs/desktop.md) for OAuth settings, security and user-data location.

The workflow [.github/workflows/desktop-build.yml](.github/workflows/desktop-build.yml)
can package **unsigned** Windows/macOS installers on GitHub-hosted runners.
These binaries must be signed/notarized before normal public distribution.

## Advanced integration features (not user sign-in)

| Platform | Inbound | Outbound | OAuth |
|---|---|---|---|
| Slack | Verified Events API Webhook | Bot direct message / configured room | OAuth v2 install, multiple workspaces |
| Telegram | Secret-token Webhook | Bot DM / group | Bot token (no personal-account OAuth) |
| LINE | Channel signature Webhook | OA push / group | Channel token (no personal-account login) |
| Discord | Signed `/tag` Interactions or opt-in Gateway | Bot DM / configured channel | User OAuth `identify`, bot installation URL |

### Cross-platform mention

1. Add approved Bot connections to the dashboard.
2. Create global identity `alice` and map her platform IDs, ideally using Discord
   OAuth verification for Discord mapping.
3. From a channel the bot can read, write `@line:alice Please review this`.
4. CrossChat queues a LINE official-account push to Alice's mapped LINE ID.

This is **not** a native foreign-app mention and cannot bypass a recipient's privacy
settings or permissions. The platform bot must be permitted to contact that user.

### Two-way room bridge

Create rule `Discord bot + channel A → Telegram bot + group B` and another rule
`Telegram bot + group B → Discord bot + channel A`. Only messages originating from
listed source rooms are relayed. Bot-generated messages are ignored to reduce loops.
Only text is forwarded; media, threads, edits and reactions are not included.

### Advanced Bot OAuth and Gateway

Set `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `SLACK_SIGNING_SECRET`,
`DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `OAUTH_CALLBACK_BASE_URL` in the server
`.env` or desktop user `settings.json`. Register exact callback paths
`/oauth/slack/callback` and `/oauth/discord/callback` with each provider.
Use the dashboard OAuth buttons. Slack installation creates a stored Bot connection;
Discord OAuth verifies an individual Discord ID against a selected identity and bot
connection. Discord bot OAuth installation is a separate action.

Discord Gateway uses the bot token and runs over outbound WebSocket, avoiding a
public webhook for Discord channel messages. General guild message reading requires
enabling the privileged **MESSAGE_CONTENT** intent on the Discord Developer Portal
and in the connection configuration. Official scope limitations apply.

## Structure

```text
desktop/                 Electron main process + isolated preload
src/app.mjs              HTTP API, webhooks, OAuth callbacks, bridge rules
src/oauth.mjs            Slack user/Bot OAuth, LINE profile OAuth, Discord identify, state/PKCE
src/gateway.mjs          Discord Gateway v10 heartbeat/reconnect/resume
src/bridge.mjs           Cross-platform mentions, room bridges, API senders
src/store.mjs            SQLite migrations, encrypted connections and outbox
src/runtime.mjs          Shared runner for browser and desktop
public/                  Traditional Chinese dashboard
.github/workflows/       Tests and Windows/macOS unsigned desktop packaging
test/                    Automated mocked-platform unit/HTTP tests
docs/                    Desktop build/architecture/roadmap
```

## Security and remaining work

All webhooks are verified before parsing, credentials are AES-256-GCM encrypted,
admin API requires a bearer key, outbound API hosts are fixed, and the desktop
renderer is sandboxed. State-based OAuth CSRF protection, Discord PKCE and limited
redirect destinations are applied. Never commit `.env`, user data, bot tokens or
private credentials.

**Not production-ready without additional work:** public HTTPS callback/webhook
hosting, privacy/consent policy, retention and deletion, permission scoping,
rate-limit recovery, signed desktop releases, and real-provider end-to-end tests.
A desktop powered off cannot receive webhooks. The Discord Gateway connection also
runs only while the desktop app is open.
